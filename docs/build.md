# Building the RG-001 contract component

The default Linux contract build uses the primary toolchain versions in [build-lock.json](../build-lock.json). The [acceptance evidence](evidence/RG-001.md) records passing CI, its tested revision and limitations. This component does not implement quota enforcement.

## Recorded Ubuntu environment

Use Ubuntu 24.04 x86_64, CMake 3.31.6 and Ninja 1.11.1. Install the exact primary Protobuf/gRPC/OpenSSL/zlib package versions from the lock:

```sh
sudo apt-get update
python3 - <<'PY'
import json, subprocess
lock = json.load(open("build-lock.json"))
packages = [name + "=" + version for name, version in lock["dependencies"]["package_versions"].items()]
subprocess.run(["sudo", "apt-get", "install", "--yes", "python3", *packages], check=True)
PY
python3 -m unittest discover -s tools/tests -v
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo -DRATEGUARD_FETCH_GRPC=OFF -DRATEGUARD_REQUIRE_PRODUCT_CONTRACTS=ON
cmake --build build --parallel 2
ctest --test-dir build --output-on-failure
python3 tools/capture_build_manifest.py --source-root . --build-dir build --codegen-tools build/codegen-tools.json --output build/build-manifest.json --build-result passed
python3 tools/verify_build_manifest.py --lock build-lock.json --manifest build/build-manifest.json
```

Pass `--build-result passed` only after build and tests succeed. The verifier rejects missing values, candidate/empty locks, package/compiler/tool/OS/architecture drift, and an observed project standard other than C++20. It uses actual compiler commands, not a declared standard alone. A different environment is unverified; record and review a deliberate lock refresh instead of silently updating versions.

## Clean reproduction

Repeat configure/build/CTest into `build-clean` with the same arguments. CI compares hashes for all 12 generated protobuf/gRPC source/header files between clean directories; both test suites must pass. This demonstrates repeatability of the declared component and generated bytes, not bit-for-bit binary or full transitive-OS reproducibility. Artifacts retain the observed runner image/version and package data; [a versioned manifest snapshot](evidence/RG-001/manifest-43327798021.json) persists after CI artifact expiry.

## Transport and schema scope

The tests cover the versioned wire layout, generated parsing/serialization, shape/configuration validation, status/commitment mapping and channel policy. The synthetic loopback retry fixture proves four calls with retries enabled versus one with enforcement arguments. Runtime clients must use `CreateEnforcementChannel`; the helper does not supply authentication or application retry logic. See the [upstream gRPC channel argument contract](https://github.com/grpc/grpc/blob/v1.51.1/include/grpc/impl/codegen/grpc_types.h) for retry/hedging semantics.

Request helper tests are not production RPC/state integration. The gRPC receive-size limit, authenticated tenant resolution, real client uncertainty handling and quota atomicity remain in their assigned later stories. Canonical policy codec/digest fixtures belong to RG-002.

## Optional source dependency experiment

`-DRATEGUARD_FETCH_GRPC=ON` retains the pinned gRPC source/submodule build as a separate experiment. It is not covered by the Ubuntu package lock. The initial all-target build exceeded the hosted job's 45-minute budget before product tests; do not claim source-lane compatibility or use it as evidence for the verified package lane.
