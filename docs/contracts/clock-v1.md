# Linux clock v1 — implementation decision record

Revision 1 · 2026-11-13 · Owner: Master technical lead. Proposed component design approved for RG-003 implementation; no executable result is claimed.

Sources: PRD 8 / SRD 5 D3–D4, FR-001/017 / LLD 5 §§5,7,16.1,16.3,17. RG-003 depends on verified RG-001 interfaces. This record selects internal mechanisms, not new quota or release behavior.

## Identity and startup

ClockIdentity contains a 16-byte kernel boot UUID; uint64 namespace device/inode; signed int64 seconds plus uint32 nanoseconds for each of monotonic and boottime namespace offsets; and int32 numeric CLOCK_MONOTONIC ID (Linux 1). Offset nanoseconds are 0..999999999. Namespace inode is nonzero. Identity compares all fields exactly; no wall/client clock conversion is permitted.

The supported target is Ubuntu 24.04 x86_64 on Linux >=5.6 with CONFIG_TIME_NS and the required readable proc entries. The kernel, privileged operator and standard unshadowed proc namespace mounts are trusted; this component does not prove hostile-host integrity. Production boot/offset files are opened once, verified with fstatfs as PROC_SUPER_MAGIC, and read bounded from that same descriptor. Namespace descriptors must report NSFS_MAGIC; fstat supplies their device/inode. Any source/type/read failure rejects startup; there is no fallback. The production platform reads the boot UUID from /proc/sys/kernel/random/boot_id, and stats /proc/self/ns/time AND /proc/self/ns/time_for_children. All four snapshots (current-before, children-before, current-after, children-after) must have identical device/inode around reading /proc/self/timens_offsets. Reject split identities, unreadable/malformed/truncated/overlong input, duplicate/missing/unknown offset rows, or a changed snapshot. Bound boot input to 64 bytes and offsets to 512 bytes; a helper must detect one byte over its bound rather than truncate. Boot UUID grammar is exactly lowercase hexadecimal 8-4-4-4-12, followed by at most one LF; no leading/trailing spaces. Offset input has exactly two nonempty rows (optional final LF), each with three tokens separated by spaces/tabs: monotonic|boottime, signed decimal seconds, unsigned decimal nanoseconds. Allow leading/trailing spaces/tabs within a row, but reject CR/NUL, empty rows, duplicate/unknown clocks, extra tokens, leading plus signs, leading zeroes except 0, and negative zero. Parse only complete decimal integers with checked conversion. Accept negative offset seconds and reject invalid offset nanoseconds.

The children comparison is essential: Linux proc_timens_show_offsets reads time_ns_for_children, while clock_gettime uses current time_ns. See [kernel implementation](https://github.com/torvalds/linux/blob/v6.8/kernel/time/namespace.c#L345) and [time_namespaces(7)](https://www.man7.org/linux/man-pages/man7/time_namespaces.7.html). Device/inode equality follows [namespaces(7)](https://www.man7.org/linux/man-pages/man7/namespaces.7.html).

Create requires expected identity supplied by the trusted epoch manifest; self-probing is not authority to become ready. Probe and factory APIs remain internal. A smoke test may deliberately use its own identity to test OS plumbing, but does not prove common Docker participant provenance. Production probing is performed on the process leader (gettid()==getpid()), before worker creation; a probe called by a nonleader thread fails. The leader-only /proc/self path is deliberate because the per-thread task directory does not expose timens_offsets on all supported kernels. Startup probing precedes worker creation; workers inherit this namespace. Runtime setns/unshare/namespace mutation is prohibited. RG-006 must enforce topology/manifest ownership and all participant comparisons before activation; absent that evidence RG-003 alone cannot prove system readiness or a quota bound.

## Sampling, ownership and errors

IClock exposes Now -> Result<MonoNanos>, Provenance -> Result<ClockIdentity>, and Healthy. LinuxMonotonicClock owns its platform port and one mutex protecting terminal health, last sample, and the complete clock_gettime(CLOCK_MONOTONIC) call/conversion/comparison. Typed internal failures never fall back, clamp, or substitute a timestamp. Failures latch for object/epoch lifetime with no reset API. A fresh object alone is not authorization to resume an epoch; supervisor integration must fence the failed epoch.

Sample seconds must be nonnegative and nanoseconds in 0..999999999. Convert to uint64 nanoseconds with checked multiplication/addition; overflow, syscall failure, or a value below the preceding serialized observation latches failure. Equal samples are legal. The factory performs an initial successful Now after identity matching and before returning an object; that sample establishes the lower observation reference. A failed startup clock read returns a typed failure, never a usable object. Later Now calls compare against the retained startup sample. Healthy and Provenance use the same mutex; Healthy is false after the first latched error, and no successful factory result is exposed before identity validation. Unsupported proc/kernel features fail startup without fallback. Provenance after failure returns the first latched error, preserving historical captured identity only in explicitly non-readiness evidence. Allocation/proc parsing happen outside the hot path.

Lock order is tenant transition lock -> clock lock; never reverse. Now holds no other callbacks, RPC, file reads or logging beyond its owned bounded platform clock-read port. A tenant transition must sample while protected and recheck deadline against that sample before mutation; expiry is now >= deadline. Advancing the clock observation on a rejected/expired attempt is legal; changing bucket state is not. The service/witness transition mapping and real deadline races remain RG-007/008 integration evidence. Global clock serialization trades simplicity for contention; latency must be measured, never inferred.

## Verification boundary

Inject only internal platform/clock dependencies. Deterministic tests cover every identity field mismatch, split namespaces and malformed bounded provenance, failed/invalid/overflow/backwards/equal samples, sticky failure, and concurrent serialized samples. Independent reviewer tests must detect a clamp-regression defect. Real Linux tests independently compare kernel/proc identity and fork/exec child identity and timestamps. Namespace-isolation tests must report unsupported permissions explicitly; missing tests do not become a PASS. Docker shared-namespace proof, full commit linearization, runtime epoch shutdown, TLS validity, benchmarks, and interval checker UNKNOWN semantics remain separately gated stories.
