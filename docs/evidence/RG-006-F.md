# RG-006 artifact layout and manifest diagnostics evidence

**Scope:** PR #21 / RG-006-F. Sources: PRD 8 / SRD 5, HLD 5, LLD 9 and [layout v1](../contracts/epoch-artifact-layout-v1.md). Full RG-006 remains In progress.

## Implemented component

The pure epoch_layout_v1 helper supplies exact canonical names and nonzero lowercase-hex epoch parse/format. BootstrapStore and ManifestStore reuse these definitions while preserving prior validation ordering, private new-only creation and publication semantics.

The diagnostic reader recognizes an optional epoch/manifest-store directory containing an empty owner.lock and a canonical manifest.json. It validates ownership, permissions, single links, bounded file types/contents and before/after identity/entry metadata. Unknown, temporary, missing or changed artifacts make the scan incomplete while safely decoded known data remains available.

Intent and manifest are scanned independently. A valid manifest remains diagnostic data when the intent is missing or corrupt. Candidate comparison occurs only after BootstrapInventory ReadyCandidate succeeds; unavailable comparison is ManifestBootstrapNotReady, while unequal complete candidates yield ManifestCandidateMismatch. Prepared/Active/Draining/Closed are retained phases, never exit or reset proof.

Nested directory entries are capped at 16. Both representations share the existing 64 MiB attempted-byte budget and 16,384 retained-record budget. Matching participants in the two artifacts consume two memory records but are not cross-epoch identity collisions. Across-epoch container/process collisions remain incomplete.

## Remaining integration

ManifestStore still receives a generic caller-supplied directory. Full EpochSupervisor composition must bind it to the validated runtime root/epoch/manifest-store while holding global ownership. Neither a path string, valid manifest nor scan_complete is an epoch capability.

Docker/OS control, pending-identity stop targets, authenticated participant activation, durable recovery/orphan reconciliation, witness validators and verified successor authorization remain pending. Witness/recovery-operation names are not accepted until their own bounded validators are integrated. No release benchmark, quota safety, full fencing or production-readiness claim is made.
