# RG-011-A1 independent strict sequence oracle evidence

**Scope:** PR24; PRD8/SRD5, HLD5, LLD12 and [contract revision2](../contracts/strict-sequence-oracle-v1.md). This verifies a synthetic model component, not full RG011 replay, a live quota service, or any release gate.

## Implemented boundary

The C++20 `StrictSequenceOracle` consumes typed policy, explicit initial state and ordered synthetic attempts. It resolves cost from configured operations and independently computes owned expected outcome/state rows. Divide-before-multiply saturation and checked integer accounting differ from production BucketMath's direct refill path. No production math, policy loader, clock, recorder or service code is imported or linked. Whole-scenario errors return no partial prefix; invalid selectors create no quota state.

## Independent and fault evidence

Developer and independently hand-calculated fixtures cover weighted/equal-time order, fractional refill, exact thresholds, LIMITED time advance, tenant isolation, invalid selectors, whole-scenario errors and legal numeric extremes. Fifteen fixed arithmetic vectors also match the existing independent Python big-integer reference. The targeted18,446,744,074ns case catches a wrapped u64 refill product that a UINT64_MAX-only example could miss.

Each generated mutant compiles against the independent fixture, then must fail its assertions: reject-all, always-allow, stale LIMITED time, debit on LIMITED, floor retry, wrong operation cost, over-cap refill, cross-tenant state, unknown-tenant default admission, equal-time reorder and u64 refill wrap. Normal positive tests must pass; compile failure cannot satisfy the expected-failure CTest controls. Generated headers are build artifacts only. These experiments are not a formal proof.

Resource fixtures exercise exact/one-over caps and allocation-error atomicity. Local optimized strict/sanitizer tests observed11 failure points, including failure after an earlier result row existed; Linux resource groups also passed. One million malformed synthetic rows exercise only the model's result cap, not the product's million-real-attempt gate. [Hand-calculated cases](RG-011-A/fixture-design.md).
