# RG-006 local lifecycle component

PR #16 implements a local gate for one immutable epoch. Sources are PRD 8, SRD 5 D5/FR-008/FR-022 and LLD 5 A-03/LLD-08. Full RG-006 acceptance remains open.

## State and ownership

The gate starts in PreActivation. Exact inventory observations must report every participant running before ACTIVE. It issues local RAII permits only while ACTIVE. BeginDrain blocks new permits; existing permits must be released before closure. Cleanup can also drain a failed startup. CLOSED is terminal, and repeating the same stop operation returns the existing result.

The immutable inventory supports authority, witness, replica and adapter roles. One authority and one witness, at least one replica and adapter, distinct host process/container identities, and one through eight replica entries are required. Replica slot IDs retain policy-v1 uint32 semantics, including zero; eight limits the entry count. Multiple adapters use unique role-local participant identifiers.

Controller observations are compared against the full participant identity, including container ID, host PID, PID-start identity, incarnation and clock identity. Stop requests go to all adapters/replicas before their exit inspections. Authority and witness shutdown follows only after that group is confirmed exited. Unknown, mismatched, failed or thrown observations leave DRAINING.

The 1,024-participant cap and role-local identifier limit of 64 ASCII letters/digits/dashes/underscores are explicit component resource choices. They add no product scale claim. The fixed input is validated before the gate allocates its internal state; caller-owned configuration has its own lifetime.

## Trusted integration boundary

An exclusive trusted supervisor must validate policy/provenance, bind the controller to real OS/runtime evidence and establish durable predecessor fencing before constructing any successor gate. Separate gate instances do not coordinate epochs. A controller must outlive its gate and use finite implementation-controlled I/O waits. Controller methods run outside the gate mutex.

The gate does not launch containers, persist inventory, acquire supervisor ownership, prevent runtime automatic restart, prove host-reboot fencing or authorize successor epochs. These are remaining RG-006 integration tasks. The future authority must still enforce its own actual commit/deadline semantics; a local permit is not a quota ALLOW.

Developer tests cover candidate rejection, multiple adapters, local phases, exact-identity mismatch, lost/failed stop evidence, startup cleanup, same-operation stop replay, and permit lifetime after gate destruction. ## Independent verification and Linux CI

Tester independently implemented adversarial and concurrency fixtures; strict local Clang and ASan/UBSan runs passed. Root repeated that independent suite successfully. Coverage includes arbitrary uint32 slot IDs, zero/nine replicas, 1,024-participant overflow, duplicate container/host PID, boot/start identity mismatch, controller exceptions, unknown exits, stop ordering, same-operation retry, permit lifetime and concurrent/reentrant activation. The initial QA fixture retained an injected stop exception during its retry and expected no exit inspections on preactivation cleanup; these fixture assumptions were corrected before publication. The current Linux run is pending. No actual Docker/OS fencing or Release A acceptance is established by these fake-controller tests.
