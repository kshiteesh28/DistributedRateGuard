# RG-006 durable manifest component evidence

Sources are PRD 8, SRD 5 (FR-008/022, D5), HLD 4 and LLD 5 §8/A-03. PR #17 targets the integration feature. Full RG-006 and Release A acceptance remain open.

## Implemented behavior

- Shared pure gate-inventory validation and exact candidate equality preserve existing gate checks.
- A versioned canonical JSON manifest binds immutable epoch, authority, policy and process/clock inventory to phase, generation and operation ID. SHA-256 detects corruption. Inputs reject duplicate/unknown keys, invalid numeric encodings, noncanonical bytes and files exceeding 4 MiB.
- CreateNew requires a new private directory and a nonzero creation operation ID. It persists PREPARED generation 1; an existing path is never reinitialized.
- Exclusive nonblocking locking is scoped to that store directory. Missing/replaced locks, symlinks, wrong owner/mode and extra hard links fail validation.
- Transitions use expected generation/digest CAS and a fixed phase graph. Caller validation/Busy/stale-CAS failures preserve a healthy writer; attempted storage/integrity failures and uncertain publication disable further writes.
- Writes sync a bounded temporary file before close/rename and sync the containing directory afterward. New-directory creation also syncs its parent. Metadata-only results distinguish NotVisible, Durable and VisibleDurabilityUnknown.
- OpenExisting reads preserved state for recovery and remains read-only, including when the file says ACTIVE. It cannot restore serving or authorize a successor epoch. Snapshots expose the last completed in-memory result while a competing write is Busy.

## Limits and remaining work

The 4 MiB encoded-file cap is an internal resource choice. It does not amend SRD D6 or assert a 4 MiB resident-memory limit. Owner locks apply per configured directory; they do not supply global supervisor exclusion. A digest authenticates neither the writer nor historical freshness, and reopened records cannot establish absence of rollback.

See the [storage contract](../contracts/manifest-store.md) for the PID-start-before-launch integration gap. Global runtime ownership, durable launch intents/non-serving bootstrap, real OS/Docker evidence, no-restart enforcement, channel closure, fenced recovery and successor activation remain future supervisor work. Ordinary fsync/crash-process tests do not prove every storage device's power-loss behavior.
