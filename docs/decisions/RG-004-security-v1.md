# RG-004 security decisions — revision 1

**Date:** 2026-11-13 · **Decision owner:** Master technical lead  
**Status:** Selected v1 implementation defaults; compatibility and deployment evidence pending. No authentication implementation or passing TLS test is claimed.  
**Sources:** PRD 8; SRD 5 D1/D2/D9; LLD 5 A-02 / §§9,16,17; [policy-v1](https://github.com/kshiteesh28/DistributedRateGuard/blob/feature/RG-002-policy-arithmetic/docs/contracts/policy-v1.md).  
**Review:** Senior Dev performed requirements extraction and pinned-source review; Master selected the defaults below. This record adds internal configuration/provisioning detail without changing canonical policy-v1 or release gates.

## Decisions and rationale

| ID | Selected behavior | Reason / verification owner |
| --- | --- | --- |
| SEC-01 | One epoch-scoped CA and one immutable leaf/key per process. Add an immutable certificate registry to the supervisor manifest: registered URI/role → SHA-256 of that leaf's DER. Bind the registry to epoch/authority/slot incarnations and validate before readiness. Keep the existing CA DER hash in policy-v1; do not add fields to its frozen encoding. | Exact leaf identity enforces no in-epoch replacement and permits safe cached validity checks. Senior Dev implements; Tester verifies startup mismatches and stale leaves. |
| SEC-02 | Replica leaf has clientAuth and serverAuth; adapter leaf clientAuth; authority leaf serverAuth. Default generated profile: EC P-256 / SHA-256, root CA=true with pathLen=0 and certificate-signing usage; leaf CA=false with digitalSignature. All purposes, strict chain constraints and validity must pass. Only one root plus directly signed leaf is supported in v1. | Replica has both TLS roles. Direct issuance avoids an unspecified intermediate-chain/provisioning feature. Do not infer a role from CN. |
| SEC-03 | Exactly one URI SAN, matching a registered URI byte-for-byte; reject duplicate/ambiguous URI SANs, embedded NULs, unknown identities and malformed values. Other SAN types cannot supply RateGuard identity. Enforce registry leaf hashes for clients and servers at both trust boundaries. | Deterministic identity, no arbitrary SAN selection or CA-signed unregistered peer. |
| SEC-04 | An adapter→replica call requires adapter role and permission for its tenant/operation. A replica→authority call additionally requires the replica's own allowed pair, fixed slot/incarnation, epoch and digest. Resolve cost from immutable policy and reject a supplied mismatch. | Every boundary checks its own caller; upstream authorization cannot widen a replica's scope. Unknown selectors never create quota state. |
| SEC-05 | Pin the selected replica's exact URI and leaf hash per adapter channel; pin the authority URI/incarnation and leaf hash per replica channel. Configuration comes from the trusted registry, never a request header. Preserve ordinary TLS chain/cryptographic verification alongside the custom verifier. | Prevents accepting another registered service merely because it shares the CA. |
| SEC-06 | Trusted wall time is an internal dependency. Production uses CLOCK_REALTIME and read-only adjtimex status; TIME_ERROR, STA_UNSYNC, STA_CLOCKERR, read/syscall failure or observed backwards time fails closed and latches trust loss for the epoch. The controlled VM, time authority and privileged operator are trusted; synchronization is a deployment precondition. | X.509 needs UTC, not quota CLOCK_MONOTONIC. This cannot detect an inaccurate but steadily advancing UTC source or prove hostile-host integrity. Actual VM preflight must pass before activation. |
| SEC-07 | Certificate validity is notBefore ≤ now < notAfter, checked for root and leaf. Server revalidates caller identity/validity/authorization at dispatch and immediately before quota/grant commit; the client wrapper validates its pinned server record before each call, and the adapter again before forwarding a received ALLOW. Expiry/trust failure before commit does not charge. | Covers queueing, reused connections and late responses. A post-commit error never reverses debit or authorizes a refund. Tests use an injected internal trusted-wall-time source. |
| SEC-08 | A channel wrapper owns the immutable expected server certificate metadata. The TLS custom verifier requires the actual peer leaf's DER hash to match that record, including on reconnect; wrapper checks therefore do not depend on ClientContext peer-leaf availability at PRE_SEND. Missing/malformed peer certificate or pin mismatch rejects TLS verification. | Resolves an unverified gRPC interceptor assumption without trusting a stale identity from another connection. Cached public metadata is not authentication by itself; successful mTLS and verifier checks remain required. |
| SEC-09 | Malformed request → INVALID_ARGUMENT; absent/untrusted/unregistered certificate identity → UNAUTHENTICATED; authenticated wrong role/pair → PERMISSION_DENIED. Clock trust loss means service unavailable, not quota LIMITED. These pre-commit failures are NotCommitted. | Preserves D1/D2. TLS handshake rejection may occur before any RPC/status exists; do not promise a structured gRPC authentication result for it. Transport loss after dispatch may be Possible commitment. |
| SEC-10 | No online revocation/live rotation. Close channels and positively fence the old epoch before replacing registry, CA or leaves. Private keys/root signing material stay outside the repository/run artifacts; root signing key is not mounted into admission/authority processes. Never log/export full certificates, credentials or keys. | Matches immutable epochs and existing retention/security scope. |
| SEC-11 | Resumed/reconnected sessions must still provide enough peer leaf metadata to verify the exact pin. Missing metadata fails closed. If target SDK/session behavior cannot satisfy this, reject that resumption path; availability/performance is not assumed. | No permissive fallback to URI-only or cached unverifiable handshake identity. Compatibility must be demonstrated before enabling the path. |

## Pinned API evidence and remaining prototypes

Senior Dev verified source support in **gRPC C++ v1.51.1**, not a successful build/handshake: experimental ExternalCertificateVerifier, TlsChannelCredentialsOptions and TlsServerCredentialsOptions expose URI SANs and peer leaf PEM. The custom verifier runs after TLS handshake before peer-check completion; rejection prevents proceeding to RPC dispatch. Full-chain PEM is not guaranteed. Keep server-certificate verification enabled and server client-certificate request policy REQUIRE_AND_VERIFY.

Primary sources: [certificate verifier API](https://github.com/grpc/grpc/blob/v1.51.1/include/grpcpp/security/tls_certificate_verifier.h), [TLS credentials options](https://github.com/grpc/grpc/blob/v1.51.1/include/grpcpp/security/tls_credentials_options.h), [TLS connector population and peer check](https://github.com/grpc/grpc/blob/v1.51.1/src/core/lib/security/security_connector/tls/tls_security_connector.cc), [adjtimex states and flags](https://man7.org/linux/man-pages/man2/adjtimex.2.html).

Before security component acceptance, require:

1. Compile/link the selected experimental APIs against the frozen Ubuntu package toolchain; prove exact wrong-URI/wrong-leaf/unknown-CA rejection before a test RPC handler executes.
2. Prove fresh, reused and resumed channel behavior, including leaf availability or deliberate fail-closed rejection, cached root/leaf expiry, and reconnect pinning.
3. Exercise incoming/outgoing role/EKU/permission checks, certificate/epoch/slot mismatch, spoofed selectors and queue-time expiry with an independent test matrix; no test-only public RPC.
4. Validate immutable manifest registry serialization/digest binding, startup consistency and fenced replacement with RG-006; do not silently change policy-v1.
5. Run read-only adjtimex plus real-time preflight in the actual Docker Linux VM. If unsupported or unsynchronized, enforcement remains unavailable; fake-clock unit tests do not pass deployment.
6. Keep implementation/test scope separate from quota service activation and product performance gates. The cost of per-call checks must be measured with witness/service integration.

No remaining behavior is delegated to an unrecorded default. Prototype/operating evidence above is still required, and this document does not claim secure provisioning or runtime PKI exists.
